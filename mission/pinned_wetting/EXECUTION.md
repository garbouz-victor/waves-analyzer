# Как агент выполняет миссию без новых ручных итераций

## Минимум инфраструктуры

Переиспользовать существующие run/config/storage/render helpers. Добавить один CLI
в `sloshing_visualization/scripts`, например `pinned_wetting_mission.py`:

    doctor / run / status / resume / verify / render / package

Эти команды ещё предстоит реализовать; пакет не делает вид, что они уже существуют.
`run` ведёт до итогового результата в пределах выбранных разрешений, а не только
до ближайшего milestone. `render` не запускает PDE скрыто. `verify` не изменяет
проверяемые данные, не подставляет отсутствующие файлы и не обновляет acceptance.

## Состояние миссии

Один EXECPLAN.md: текущее решение, завершённое, следующий шаг, команды и evidence.
Машинный state содержит реальные run IDs/пути/process IDs/exit codes/ресурсы,
не выдуманный progress=63%. Прогресс: completed milestones и actual t/t_end.

Разделять три уровня восстановления:
- контекст Codex: read plan/state, затем продолжить thread;
- job: PID/container ID + process start identity + heartbeat + exit status;
- CFD: checkpoint физического состояния, W/H, retained fields, timestep history.

Перед resume проверить, не жив ли прежний job. Не делать второй solve параллельно.
При недоступном API/терминале сохранить state и точную resume-команду; ограничения
сессии не равны научному failure. Не обещать бессрочный background-run без исполнителя.

## Конечный автомат

NOT_STARTED -> AUDIT -> MODEL_DECISION -> PREVIEW -> TARGET_RUN -> REFINEMENT
-> RENDER -> VERIFY -> COMPLETE_FOR_DECLARED_MODEL.

Ошибка допускает возврат в зависимый этап с новым run ID. MODEL_DECISION выбирает
конкретные уравнения/closure до дорогих runs; не бесконечный literature review.
Блокирующие финальные статусы: NEEDS_MODEL_DECISION, RESOURCE_LIMIT, FAILED.
Полезное preview сохраняется отдельно, но не преобразует их в COMPLETE.

## Исправления вместо каскада STOP

Обычная ошибка теста, path, ffmpeg или allocation — агент диагностирует и исправляет.
Численный rejected step не принимается. Предопределённые adaptive stepping/retry
допустимы в НОВОМ target solver, если они описаны, устойчивы, записаны и учитываются
в convergence; запреты исторических fixed schedules не наследуются автоматически.

При провале согласованности/массы/энергии — сохранить неудачный run, исправить
причину, сделать новый. До двух содержательных попыток на blocker. Не ослаблять
научный target после просмотра результата и не сбрасывать счётчик ресурсов.

Неразрешённая реальная смена физики требует одного конкретного пользовательского
решения. До такого вопроса закончить независимые полезные части. Не просить
человека выбрать JSON versus CSV или разрешить очевидный bugfix.

## Ресурсы

Defaults 12 часов локальных jobs, 40 GiB новых данных, 65% RAM и один тяжёлый job
— предложения пакета. Прочитать фактически выбранный CONFIG перед запуском.
Вести бюджет через контексты/перезапуски. Если уже есть существующий процесс,
прочитать его ledger. Не покупать compute, не переходить на API key из-за лимитов.

Прогноз advisory: превышение грубой оценки не означает неправильность PDE.
Но нельзя слепо запускать явно не помещающуюся в память задачу. Начать с малого
pilot и разумного плана сетки; actual hard caps и безопасность сохраняются.
Остановку при достижении cap делать корректно: checkpoint, exit status, отчёт.
Суммировать измеренные интервалы работы job; не смешивать CPU-seconds и wall time.
Вспомогательная инфраструктура — не более 10% бюджета, если она не является
непосредственной причиной отсутствия конечного результата.

## Provenance без паралича

Новый feature-case независим от старой 127-step trajectory и её cost authorization.
Не менять historical guards/prefixes и не заставлять всю новую работу ждать их
fsync-исследования. Старые артефакты read-only references.

Для нового run: numerical source/content hash, physical config, solver controls,
mesh, initial state, output schema, настоящий execution HEAD. Смена commit из-за
документов не меняет numerical identity. Но изменение математического solver/closure
или physical config требует нового run ID; уже измеренную trajectory не склеивать
из несовместимых источников.

## Независимое verify

Разнести implementation и audit. Reviewer проверяет native data и PHYSICS,
сохраняет review.md с ссылками. Наличие tests PASS или флага passed=true в manifest
не заменяет проверку. Включить отрицательные fixtures. При невозможности отдельного
агента провести отдельный read-only review pass, не менять тесты ради результата.

## Commit и завершение

Локальные осмысленные commits допустимы. Не пушить. Финальный ответ только после
полного verify либо настоящего blocker/лимита. Он содержит пути к артефактам,
реальный статус, использованные допущения и одну команду дальнейшего уточнения.
Не ставить числовой «процент готовности модели» без измеримого смысла.
