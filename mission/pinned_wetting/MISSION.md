# PW1 — одна миссия до финальной анимации

## Конечная цель

Сделать воспроизводимый Python-расчёт колебаний жидкости в прямоугольном сосуде
и финальную анимацию 0–5 с для правила **необратимого смачивания**:
однажды достигнутая жидкостью точка стены навсегда связана непрерывным остаточным
слоем с жидкостью ниже. Толщину слоя сейчас не определяем.

Результат должен отвечать: насколько первая волна поднимает жидкость слева;
создаётся ли новый рекорд позже; где остаётся верхний край смоченной области
на каждой стенке, когда основная масса жидкости отходит вниз.
Нельзя заранее обещать или навязывать рекорд 3/4.

Прочитать `PHYSICS.md` как нормативную постановку. Последние слова пользователя
важнее прежних ошибочных трактовок «контактная линия сползает/переприлипает».
Исходные изображения — качественные пояснения, не точные геометрические данные;
специально не включаем противоречивые сгенерированные схемы в эталон приёмки.

## Приоритеты

1. Физический смысл последнего пользовательского правила и честность результата.
2. Реальные данные, сходимость и соблюдение явно выбранной модели.
3. Финальная понятная анимация и воспроизводимость.
4. Ограничения ресурсов и сохранность пользовательских данных.
5. Внутренняя элегантность, дополнительные dashboards и универсальность — необязательны.

Не расширяй миссию до универсального CHNS framework, наномолекулярной динамики,
поиска оптимального CI или исследования исторического fsync.

## Что уже готово, а что предстоит

Прочитай `REPO_MAP.md`. Пакет даёт задачу, конфигурацию и несколько вспомогательных
проверок, но не новый PDE solver. Пользователь просит результат, а не только код.
Переиспользуй linear FEM и STEP2 renderer для reference/контроля там, где допустимо.
Поздний full phase-rate CHNS ограничен matched density/zero force — нельзя просто
снять guard и назвать его solver гравитационного сосуда.

Важно: ни `H(t)=running_max(R(t))`, ни синяя полоска сами не определяют `R(t)`.
До production нужен корректный расчёт достижения стены выбранной моделью.
Экстраполированный bulk crest на ненулевом расстоянии от стены не является
доказательством её смачивания.

## Автономность

Работай в отдельной feature-ветке от актуального master; исторические ветки/данные
не изменять. Если branch/worktree уже создан, не пересоздавай. Проверяй реальные
файлы, не считай ссылки README доказательством наличия больших ignored HDF5.

После успешного milestone переходи дальше автоматически. Можно делать commits,
но commit не завершает миссию. Короткие сообщения о ходе работы допустимы; не
заканчивай всю работу фразой «следующий шаг — подготовить ещё один промпт».

При сбое сделай целевое исправление и повтори только зависимый этап. Две
содержательные попытки на blocker; если он всё ещё мешает, сузь вывод, сохрани
артефакты и объясни ровно недостающее физическое решение/ресурс, без новой цепочки
инфраструктурных итераций. Не публикуй rejected state как accepted.

## M0 — контракт, аудит и сквозной preview

Проверь рабочую среду, доступные CPUs/RAM/disk, Python, solver libraries и ffmpeg.
Запиши выбранный case в `resolved_case.json`: все defaults с происхождением,
геометрия/глубина, параметры, уравнения и wall treatment. Отдельно отметь
микроскопические величины, которые не рассчитываются.

Выбери простейший путь, который может выполнить PHYSICS; не выбирать путь только
по удобству красивой картинки. В `model_decision.md` на 1–2 страницах объясни,
как вычисляется фактическое макроскопическое касание и как живёт остаточный слой.
Уточни, используется ли ведущепорядковое пренебрежение его объёмом/обратным влиянием.

Сделай ранний сквозной preview: короткий расчёт -> состояние -> wet history -> MP4.
Если он из старого неподходящего linear case, на видео крупно `REFERENCE / NOT TARGET`.
Это демонстрация pipeline, не основание COMPLETE. Синтетические unit-test trajectories
можно использовать только с маркировкой `SYNTHETIC`, отдельно от scientific output.

## M1 — рабочая целевая модель и ограниченные тесты

Реализуй недостающий wall/subgrid слой и реальное движение макроповерхности.
Решатель должен хранить W/H в state/checkpoint, а не вычислять их только renderer.
Должна быть формальная связь L_macro + retained coating, обеспечивающая непрерывность
смоченного участка. Для ведущепорядковой one-way модели это явно заявленная
аппроксимация, а не разрешённая молекулярная плёнка.

Проверь минимально необходимое: начальная прямая, нулевая скорость в t=0,
масса, уравнение несжимаемости в своей дискретизации, соответствие wall BC,
необратимость, lower-connected coating, отсутствие ложного смачивания хвостами
интерполяции, продолжение после checkpoint, восстановление run IDs и marker IDs.
Проверь один простой независимый гидродинамический reference, подходящий методу.

Не заставляй проходить все старые matched-density stiff-bump milestones, если
новый расчёт их не использует. Нужна проверка реального target path, не коллекция PASS.

## M2 — полный горизонт и уточнение

Сделай целевой baseline до 5 с; сохрани данные и сразу рабочий preliminary MP4.
Это ещё не финальный qualified результат. Существование предварительного видео
не снимает следующие проверки.

Отдельно уточни dt при фиксированной сетке и сетку при достаточно малом dt.
Проверь поверхность, макроуровни у стенок, H_L/H_R, высоту/время первого подъёма.
Дай пользователю команды дальнейшего уточнения (`--mesh-level`, `--dt-scale` или
эквиваленты). Больше ресурсов должны уточнять эту же модель, а не менять физику.

Пороговые значения в ACCEPTANCE — предлагаемые критерии инженерного выпуска,
не обещанная a priori ошибка. Если отличия выше порога, сделай одно адресное
уточнение, не ослабляй критерий. Нельзя заявлять доказанный порядок сходимости
по двум точкам. Неисполненные вычисления отмечай NOT RUN.

## M3 — финальные артефакты и независимый review

Выпусти final_animation.mp4, wall_detail.mp4, данные и 11 срезов поверхности
через 0.5 с, runup/wetting histories, отчёт об уточнении, FINAL_REPORT.md,
manifest.json, verification.json. Offline explorer полезен, но не должен
мешать выпуску основного MP4 и данных: допустим минимальный HTML-проигрыватель
с реальными скачиваемыми данными, без декоративного сложного dashboard.

Выполни полное ffmpeg-декодирование видео, проверь fps/размер/cadence; просмотри
представительные кадры и привязку точек к data coordinates. Каждое событие
смачивания должно быть связано с accepted solver state. Никаких заранее
нарисованных волн поверх несовместимого FEM dataset.

Независимый reviewer (другой контекст/подзадача при наличии; иначе отдельный проход)
должен прочесть PHYSICS и данные, а не только финальный текст. Он запускает
негативные проверки из OUTPUT_SCHEMA. Не оценивай модель только своим `PASS=true`.

## Статусы

`COMPLETE_FOR_DECLARED_MODEL`: цель достигнута для явно указанной модели,
ограничения не спрятаны, acceptance пройден и файлы существуют.
`PREVIEW_ONLY`: есть видео, но модель/контакт/точность ещё не квалифицированы.
`NEEDS_MODEL_DECISION`: требуется изменение исходных физических предположений,
которое не покрывается разрешённым подсеточным описанием остаточного слоя.
`RESOURCE_LIMIT`: фактический локальный бюджет исчерпан; полезные артефакты сохранены.
`FAILED`: воспроизводимый численный/программный дефект после целевых попыток.

Не использовать глобальное `MODEL VALIDATED`: закончить требуется один case.

## Финальный ответ агента

Путь к MP4/HTML, какая модель посчитана, параметры, максимумы и их времена,
что осталось смоченным, результаты уточнения, фактические ограничения,
команда повторения/повышения точности, tests и настоящий статус. Не обещать
продолжение «в фоне» без реально работающего процесса и его идентификатора.
