# Независимый review: LEFT Navier / RIGHT no-slip

Вердикт: `PASS_DISCRETE_EQUATIONS_REJECT_TARGET`. Это **не** приёмка целевого
расчёта и не `COMPLETE_FOR_DECLARED_MODEL`. Три реальные траектории линейной
модели до 1 с прошли независимый аудит дискретных уравнений, источников,
граничных условий и coating-state. Однако hard screen по наклону не пройден,
а пространственное уточнение всей поверхности также не прошло порог 5%.
Целевой горизонт 5 с, квалифицированные final MP4 и чувствительность к b_left
для исправленной постановки — `NOT_RUN`.

## Что проверено независимо

Reviewer работал в отдельном контексте. Новый `asymmetric_verify.py` не импортирует
production `NavierFEM` или `LeftNavierFEM`. Он использует общий базовый FEM для
сетки, объёмных форм и пространств, но независимо собирает:

- fixed = LEFT horizontal ∪ RIGHT both components ∪ BOTTOM both components;
- полную положительную LEFT-only матрицу трения из скалярной граничной массы,
  в отличие от production-векторной формы;
- reduced endpoint trace с числом ненулевых элементов `[1, 0]`;
- SDIRK2 стадии, импульс, слабую несжимаемость, кинематику eta и раздельный
  энергетический баланс из сохранённых скоростей, давлений и eta.

Проверяется и полная K_wall до редукции. Поэтому лишний RIGHT Navier term
отвергается даже тогда, когда правые Dirichlet DOFs обнуляют его физический вклад.
В каждом accepted state проверены постоянные eta_RIGHT = H_RIGHT = z2,
отсутствие новых RIGHT records, начальная прямая и нулевая скорость,
H_LEFT = running maximum фактического LEFT endpoint, W_i = [−d,H_i],
неподвижный каталог маркеров и соответствие checkpoint-state.

На LEFT n=−e_x; (Tn)_tau = −(nu/b_left)w даёт положительный член
(nu/b_left)∫LEFT w v_tau в слабой форме и потерю энергии
(nu/b_left)∫LEFT w² ≥ 0. Независимый channel benchmark проверяет

    w = G/(2 nu) (a²−x²) + Ga b_left/[nu(b_left+2a)] (a−x),
    w(+a)=0,  w′(−a)=w(−a)/b_left,  −nu w″=G.

Тесты b_left=.25,.50,1.00 проходят с относительной ошибкой порядка 10⁻¹⁴.
Это проверка знака/граничного оператора, а не валидация движущейся поверхности.

## Единственный blocker и его воспроизведение

`PW1_PINNED_RIGHT_LINEAR_APPLICABILITY`: при неизменных исправленных BC
закреплённый правый endpoint соединяется с движущейся внутренней поверхностью
через очень крутой край. Линеаризованная геометрия не проходит заранее
объявленный all-edge slope screen уже в начале пилота; h/2 увеличивает
наклон, а не устраняет проблему, и выявляет непройденный surface refinement.

Это не утверждение невозможности weak solution и не доказательство ошибки
знака Navier или освобождения правой стенки. Равномерная C1 регулярность в
точке встречи no-slip и free-stress не предполагалась. Однако исключать эту
точку/edge из принятого hard screen, менять b_left, alpha, nu, sigma или BC,
подменять endpoint интерьерным гребнем либо сглаживать визуализацию нельзя.
Для физически квалифицированного 0–5 с при этих BC требуется следующий
модельный шаг с разрешённой нелинейной геометрией/кинематикой и отдельной
валидацией, а не ещё один запуск той же неквалифицированной линейной модели.

Дешёвое воспроизведение witness из корня репозитория, без нового solve:

```sh
cd sloshing_visualization
PYTHONPATH=src python -c 'from pathlib import Path; from sloshing.pinned_wetting.asymmetric_verify import surface_applicability; print(surface_applicability(Path("results/pinned_wetting/left_navier_right_noslip/leftnavier-pilot_space-afafc6be0b5f/native.h5")))'
```

Использовать Python окружения с объявленными зависимостями проекта. Для полного
операторного повторения заменить `surface_applicability` на `verify_native`;
запускать по очереди под mission job lock. Cheap geometry-only helper никогда
не является заменой полного аудита уравнений.
